# サンマ帳 要件定義書 v1.2

作成：2026-10-18 18:05（JST）／改訂：2026-10-18（構成を Supabase から Cloudflare に変更）

三人麻雀の半荘結果を入れると、pt・金額・成績・精算額が自動で出て、グループ全員がスマホで同じ画面を見て編集できるウェブアプリ。

---

## 0. この文書の使い方

- 要件には番号を振る。F＝機能、W＝警告、N＝非機能。修正や追加を頼むときはこの番号を書く（例：F-09のチップ記録にメモ欄を足して）。
- 優先度は3段階。MUST＝初版に必須、SHOULD＝初版に入れたい、COULD＝後回しでよい。
- Claude Codeには、作業に関係する節だけを読ませる。全文を毎回読ませない。

---

## 1. 目的と背景

### 1.1 目的
- 半荘ごとの素点から、pt・円・順位を自動計算する
- チップ・場代を含めた最終的な精算額を出す
- 成績（トップ率など）を自動で集計する
- グループ全員がURLから見られ、誰でも編集できる
- すべての変更を消せない履歴として残し、点数の書き換えを防ぐ

### 1.2 今のExcel運用の問題（作り直す理由）
- 同点のとき順位の式（RANK）が両者を同じ順位にしてしまい、手動のチェックが必要
- チップや場代を、表の下の手入力行で調整している
- 全員で同時に見たり直したりできない
- 誰がいつ何を直したか分からない
- 4〜5人の交代（抜け番）に、シートを分けて対応している

## 2. 利用者と権限

| 項目 | 決定内容 |
|---|---|
| 編集できる人 | グループに入った全員（リーダー限定にしない） |
| 書き換え対策 | すべての操作を履歴に残す。履歴は誰も消せない・直せない。全員が見られる |
| 入室方法 | グループのURLを開き、合言葉を入れる |
| 本人の特定 | 初回に、メンバー一覧から自分の名前を選ぶ。端末ごとに記憶する |
| 内部の仕組み | 入室時にサーバーが端末ごとのIDと署名付きの鍵を発行し、履歴に端末IDと名前を両方記録する |

補足：名前の選択は自己申告なので、なりすましを完全には防げない。ただし履歴に端末IDが残るため、同じ端末が別の名前で操作すれば分かる。厳密にしたくなったらGoogleログインを足す（F-22）。

## 3. 用語

| 用語 | 意味 |
|---|---|
| グループ | いつも打つ仲間の単位。URLと合言葉はグループごと |
| メンバー | グループに登録された打ち手。4人以上でもよい |
| セッション | 1回の集まり（1日分）。精算はセッション単位 |
| 半荘 | 1ゲーム。毎回メンバーから3人が入る |
| 素点 | 半荘終了時の持ち点。百点単位の整数で入力する（320＝32,000点） |
| pt | 素点から返しを引き、ウマ・オカを足した点数。1pt＝1,000点 |
| 麻雀収支 | pt × レート（円） |
| 最終収支 | 麻雀収支＋チップ収支＋調整 |

## 4. 計算ルール（三麻標準のみ）

### 4.1 初期値（Excelの現行ルールを引き継ぐ）

| 項目 | 値 | 変更 |
|---|---|---|
| 持ち点 | 35,000点 | 固定 |
| 返し | 40,000点 | 固定 |
| ウマ | 2位 0、3位 −10 | 固定 |
| オカ | (40,000−35,000)×3人 ＝ 15pt（1位が受け取る） | 固定 |
| 3人の合計 | 105,000点（入力の確認に使う） | 固定 |
| レート | 1pt＝60円（Excelの0.6） | セッションごとに設定。10円刻み |
| チップ | 1枚＝100円 | セッションごとに設定。50円刻み、50円以上 |

固定の値もコードでは `src/lib/mahjong/rules.ts` の定数にまとめ、後から変えやすくする。

### 4.2 計算式
1. 素点の高い順に1〜3位を決める。同点なら 4.3 の指定に従う
2. 2位のpt ＝ (素点 − 40,000) ÷ 1,000
3. 3位のpt ＝ (素点 − 40,000) ÷ 1,000 − 10
4. 1位のpt ＝ −(2位のpt ＋ 3位のpt)（3人のptの合計は必ず0）
5. 麻雀収支（円）＝ pt × レート

- 素点は百点単位なので、ptは小数第1位まで出る（例：72,400点の2位 → 32.4pt）
- レートを10円刻みに限るので、円は必ず整数になる。端数処理は不要
- 素点はマイナスも入力できる（飛び）

### 4.3 同点
- 素点が同じ人がいるときだけ、入力画面に「どちらを上の順位にするか」の選択を出す
- 選ぶまで保存できない
- 3人とも同点（35,000点ずつ）の場合も同じ方法で順番を決める

### 4.4 チップ
- チップ収支 ＝ 増減枚数 × チップ単価
- 1回の記録で、参加者全員の増減の合計は0でなければならない

### 4.5 作らないもの
- 四人麻雀
- 沈みウマ（Excelの別シート）
- 役・符の計算

## 5. 機能要件

### 5.1 グループ・入室

| ID | 優先 | 内容 |
|---|---|---|
| F-01 | MUST | グループを作る。名前と合言葉を決める。作成後にURLを表示し、コピーできる |
| F-02 | MUST | URLを開くと合言葉の入力画面。正しければ入室し、自分の名前をメンバー一覧から選ぶ（新しく追加もできる）。次回からは入力不要 |
| F-03 | MUST | メンバー管理。追加・名前変更・色の設定・非表示（成績から消さずに一覧から隠す） |

### 5.2 セッション

| ID | 優先 | 内容 |
|---|---|---|
| F-04 | MUST | セッションを作る。日付・タイトル（省略時は日付）・レート・チップ単価。前回のセッションの値を初期値にする |

### 5.3 半荘の記録

| ID | 優先 | 内容 |
|---|---|---|
| F-05 | MUST | 半荘を記録する。①3人を選ぶ（前の半荘の3人を初期値にし、1人だけ入れ替える操作を簡単にする）②素点を入れる（2人分を入れると3人目は105,000点から自動で埋まる。手で直してもよい）③合計が105,000点でなければ差を表示し、保存させない ④同点なら順位を選ばせる ⑤写真を付けられる ⑥保存すると順位・pt・円を表示する |
| F-06 | MUST | 半荘一覧。各行に通し番号・3人の順位・素点・pt・円。変更されたことがある半荘には「変更あり」の印、写真があればアイコン。新しい半荘を上に表示 |
| F-07 | MUST | 半荘の編集・削除。削除は記録を残したまま非表示にする（論理削除）。削除した半荘は履歴画面から復元できる |
| F-08 | MUST | 途中参加・途中退出。半荘ごとに3人を選ぶので、セッションの参加人数に上限はない。退出する人は「途中精算」を押すと、その時点の本人の最終収支と払う相手・金額が出る。「精算済み」にすると、その時点の金額を記録する |

### 5.4 チップ・調整・精算

| ID | 優先 | 内容 |
|---|---|---|
| F-09 | MUST | チップ（バイイン方式、v1.2で変更）。バイイン（買った額・円）と返却（返した額・円）をその都度記録する。複数人を選ぶと同じ額が入る。最後（または途中で抜けるとき）に手持ち枚数を入れる。チップ収支＝最新の枚数×単価 − バイイン合計 ＋ 返却合計。数えた枚数の合計と（バイイン−返却）が合わなければ警告を出す |
| F-10 | MUST | 調整（場代など）。個人の最終収支に直接プラス・マイナスの円を入れる。メモ必須。種類は2つ：外部（店に払う分など。送金の計算に入れない）／メンバー間（立て替えなど。合計0が条件で、送金の計算に入れる） |
| F-11 | SHOULD | 場代の割り振り補助。金額と払い方（全員で均等／特定の人だけ／打った半荘数に応じて）を選ぶと、F-10の調整を自動で作る。作られた調整は手で直せる |
| F-12 | MUST | 精算画面。人ごとに 麻雀収支・チップ収支・調整・最終収支 を表で表示。精算済みの人には印 |
| F-13 | SHOULD | 送金リスト。誰が誰にいくら払うかを、少ない回数（人数−1回以内）で表示。対象は麻雀収支＋チップ収支＋メンバー間の調整 |

### 5.5 成績

| ID | 優先 | 内容 |
|---|---|---|
| F-14 | MUST | 成績表。セッション別と通算を切り替える。項目は 5.7 の通り。列をタップすると並べ替え |
| F-15 | SHOULD | 収支推移グラフ。横軸＝半荘の通し番号、縦軸＝累計の麻雀収支（円）。人ごとに線を分ける |

### 5.6 写真・履歴・その他

| ID | 優先 | 内容 |
|---|---|---|
| F-16 | — | 半荘・セッションへの写真は v1.2 で廃止。写真は役満の記念写真（F-24）と背景写真（F-26）だけ |
| F-17 | MUST | 変更履歴。作成・変更・削除・復元・設定変更・写真の追加と削除を、日時・操作者の名前・端末ID・変更前・変更後で記録する。誰も消せない・直せない。画面では新しい順に表示し、「第12半荘 赤堀 32,000→33,000」のように差分を読める形で出す。半荘・人・操作の種類で絞り込める。半荘の詳細から、その半荘だけの履歴に飛べる |
| F-18 | SHOULD | リアルタイム反映。誰かが保存すると、開いている全員の画面が自動で更新される |
| F-19 | SHOULD | CSV書き出し。半荘一覧・成績・精算をCSVで保存 |
| F-20 | COULD | 今のExcelからの取り込み（名前・素点・レート） |
| F-21 | COULD | 対戦相性（誰と同じ卓のときに成績が良いか） |
| F-22 | COULD | Googleログイン（本人確認を厳密にする） |
| F-23 | COULD | 閲覧専用のURL（編集できないリンク） |
| F-24 | MUST | 役満。半荘の記録時に「役満が出た」で、出した人と役の名前（任意）を記録する。チップの計算には関わらない。役満の殿堂の画面に、日付・人・役・記念写真を一覧で出す |
| F-25 | MUST | 抜け番の提案。直近4半荘に出た人（精算済みは除く）から、これまで抜けた順番を読み取り、次の3人を最初から選んでおく。一度も抜けていない人が先（打った回数が多い順）、次に最後に抜けたのが古い人 |
| F-26 | MUST | 背景写真。設定で1枚選ぶと、グループ全員の画面の背景に薄く表示する |
| F-27 | MUST | 始めやすさ（v1.2）。最初の画面は名前の入力だけ。グループ名は既定値、合言葉はなし（あとで設定）。対局は前回のレート・チップ単価でワンタップで始まる |

### 5.7 成績の項目と定義

| 項目 | 定義 |
|---|---|
| 半荘数 | 参加した半荘の数（削除分を除く） |
| 1位・2位・3位の回数 | 順位ごとの回数 |
| トップ率 | 1位の回数 ÷ 半荘数 |
| 連対率 | (1位＋2位の回数) ÷ 半荘数 |
| ラス率 | 3位の回数 ÷ 半荘数 |
| 平均着順 | 順位の平均（小数第2位まで） |
| 平均素点 | 素点の平均 |
| 最高素点・最低素点 | 1半荘での最大・最小 |
| 飛び率 | 素点が0点未満で終わった回数 ÷ 半荘数（0点ちょうどは含めない） |
| 合計pt・平均pt | ptの合計と平均 |
| 麻雀収支 | 円の合計 |
| 最大勝ち・最大負け | 1半荘での円の最大・最小 |
| 最大連続トップ・最大連続ラス | 本人が参加した半荘を順に並べたときの最長連続 |

## 6. 警告（確認画面）

どの警告も、OKを押せば実行できる（W-05だけは保存できない）。実行した内容はすべて履歴に残る。

| ID | 条件 | 表示する内容 |
|---|---|---|
| W-01 | 最新でない半荘を変更・削除する | 変更前と変更後の素点、各人の円の増減、「この変更は履歴に残り、全員が見られます」 |
| W-02 | チップ単価を変える | 変更前後の単価と、各人のチップ収支の増減 |
| W-03 | レートを変える | 適用範囲を選ばせる：これから記録する半荘だけ（初期値）／このセッションの全半荘。全半荘を選んだ場合は各人の増減を表示 |
| W-04 | 精算済みの人の金額が変わる操作 | 対象者の名前と、精算済みの金額との差 |
| W-05 | 素点の合計が105,000点でない | 差を表示し、保存ボタンを押せなくする |
| W-06 | 削除全般（半荘・チップ・調整・写真） | 何を削除するか、復元できること |

W-01の範囲：最新の半荘（いちばん新しい1件）は警告なしで直せる。入力直後の打ち間違いを直すため。それより前の半荘はすべて警告を出す。

## 7. 画面

スマホの縦画面で片手操作を前提にする。下部にタブを置く：記録／成績／精算／履歴／設定。

| 画面 | 主な中身 |
|---|---|
| 入室 | 合言葉の入力 → 自分の名前を選ぶ |
| グループのトップ | セッション一覧（日付・半荘数・自分の収支）、新しいセッションのボタン |
| 記録（セッション） | 上部に現在の最終収支のランキング（横に並ぶカード）。大きな「半荘を記録」ボタン。下に半荘一覧（F-06） |
| 半荘の入力 | 3人の選択 → 素点の入力（数字キー、百点単位）→ 合計の表示（あと◯点）→ 同点時の選択 → 写真 → 保存 |
| 半荘の詳細 | 順位・素点・pt・円、写真、この半荘の履歴へのリンク、編集・削除 |
| 成績 | 成績表（F-14）、推移グラフ（F-15） |
| 精算 | 精算表（F-12）、送金リスト（F-13）、チップ記録（F-09）、調整（F-10, F-11）、途中精算（F-08） |
| 履歴 | 時系列の一覧（F-17）、絞り込み |
| 設定 | レート・チップ単価（W-02, W-03）、メンバー管理（F-03）、グループのURLと合言葉の変更、CSV書き出し |

見た目の方針：
- 数字は大きく、桁がそろう等幅の数字にする
- プラスとマイナスは色に加えて＋/−の記号でも区別する（色だけに頼らない）
- 円は3桁ごとにカンマ、ptは小数第1位まで
- メンバーごとに色を固定し、グラフ・カード・一覧で同じ色を使う
- ボタンは指で押しやすい大きさ（高さ44px以上）

## 8. データ設計（Cloudflare D1 / SQLite）

方針：
- 物理削除はしない。`deleted_at` を入れて論理削除する
- 1つの操作が履歴1件になるよう、半荘の3人分の素点は1行のJSONにまとめる
- 順位・pt・円はDBに保存せず、毎回 `src/shared/mahjong.ts` で計算する。記録時のレートは半荘ごとに保存する
- テーブルは初回アクセス時に自動で作る（worker/schema.ts）

| テーブル | 主な列 |
|---|---|
| groups | id, name, join_salt, join_hash（合言葉はPBKDF2でハッシュ化）, created_at |
| members | id, group_id, name, color, sort, hidden, created_at |
| sessions | id, group_id, title, played_on, rate（10の倍数）, chip_yen（50の倍数・50以上）, created_at, deleted_at |
| games | id, group_id, session_id, seq, rate, scores（JSON：`[{memberId, score, tie?}]`）, created_at, updated_at, deleted_at |
| chips | id, group_id, session_id, lines（JSON：`[{memberId, count}]`）, memo, created_at, deleted_at |
| adjustments | id, group_id, session_id, kind（external / internal）, lines（JSON：`[{memberId, yen}]`）, memo, created_at, deleted_at |
| settlements | id, group_id, session_id, member_id, yen, created_at, deleted_at |
| photos | id, group_id, session_id, game_id, width, height, created_at, deleted_at（画像本体はKV） |
| audit_logs | id, group_id, entity, entity_id, action（insert / update / delete / restore）, before, after, actor_member_id, actor_name, actor_device, created_at |
| join_attempts | group_id, window_start, failures（合言葉の連続失敗の記録） |
| meta | key, value（署名用の秘密鍵。初回に自動生成） |

### 8.1 履歴を書き換えられなくする仕組み
- データを変えるAPIは、変更と audit_logs への1行追加を同じ一括処理（db.batch）で行う。片方だけ成功することはない
- audit_logs には UPDATE と DELETE を拒否するトリガーを付けている。管理者がDBを直接操作しても書き換えられない
- アプリには履歴を変えるAPIがない

### 8.2 アクセス制御
- 入室：合言葉が正しければ、`グループID.端末ID.署名` の鍵を発行する。署名はサーバーだけが持つ秘密鍵によるHMAC
- 以降のAPIはこの鍵を確認し、そのグループの行だけを読み書きできる
- 合言葉を10分間に10回間違えると、そのグループへの入室を10分止める
- 操作者の名前は、端末で選んだメンバーを毎回送り、サーバーでグループのメンバーか確認してから履歴に残す

### 8.3 写真の保存
- Cloudflare KV（無料枠1GB）。キーは `{group_id}/{photo_id}`
- 表示も鍵が必要（URLに鍵を付ける）。鍵がなければ見られない

## 11. 受け入れテスト（計算）

ExcelのデータでExcelと同じ結果になることを確かめた値。レート60円。素点は百点単位。
