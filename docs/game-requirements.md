# オンライン三麻 要件定義書 v0.5

作成：2026-10-25 17:00（JST）／更新：2026-10-25（チップ祝儀制・符なし固定点数表・西入延長・金5・待ち牌表示・デバッグ重視・AIアシスト一旦なし を反映 v0.5）

仲間内で遊ぶ、実際に打てる三人麻雀のウェブアプリ。全赤・花あり・白ポッチあり・チップ（祝儀）ありのハウスルール。雀魂に似た最小限の画面で、3人が別々の端末から同じ卓に入ってオンライン対局し、終わったら既存の「対戦記録」アプリに自動で結果が入って精算まで完結する。

番号（R=ルール、P=進行、I=統合、D=画面、C=チップ、DBG=デバッグ、N=非機能）で参照する。

---

## 1. 何を作るか

- 3人が別端末から同じ卓に入り、リアルタイムで三麻を打てる
- 卓への入室は対戦記録アプリのグループ内から行う。毎回リンクをコピーする必要はない（I-07）
- 牌山・配牌・ツモ・打牌・鳴き（ポン・カン）・リーチ・和了・流局・点数移動・チップ移動まで通して動く
- 相手の手牌は見えない（サーバーが本当の状態を持ち、各自には自分の手牌だけ送る）
- 点数計算は符なしの固定点数表＋全赤・金5・花・白ポッチ・チップ込みで自動
- 打つ→終局→対戦記録へ自動登録→精算まで、すべてオンラインで完結
- 画面は雀魂風だが最小限。キャラ選択・演出・課金・ランキングはなし

作らないもの（今回）：CPU対戦、観戦チャット、戦績の長期統計、AIアシスト（§7の判断で一旦なし）。

## 2. ルール定義

### 2.1 基本（三麻標準）

| ID | 内容 |
|---|---|
| R-01 | 使う牌：萬子は一と九のみ、筒子・索子は一〜九、字牌（東南西北白發中）すべて。計27種・108枚＋花4枚＝112枚 |
| R-02 | 鳴き：ポン・カン（明槓・暗槓・加槓）あり。チーなし。喰い替え禁止 |
| R-03 | 持ち点35,000点、返し40,000点。オカ15,000点は1位へ。ウマは対戦記録アプリと同じ（2位0・3位−10、1位がその裏返し） |
| R-04 | 東南戦。各局で親が移動。西入あり（P-03） |
| R-05 | ツモ損なし。ツモの支払い配分は点数表（R-42）のとおり |
| R-06 | 北：全員の自風として扱う。誰が持っても役牌になり、北の刻子・槓子で1翻。抜きドラにはしない |
| R-07 | 喰いタンあり、後付けあり、形式テンパイあり。ローカル役は入れない（ただし流し役満は採用、R-07b） |
| R-07b | 流し役満：自分の捨て牌がすべて么九牌（1・9・字牌）で、一度も鳴かれていなければ、流局時に役満。和了扱いで連荘 |

### 2.2 ドラ・赤・金

| ID | 内容 |
|---|---|
| R-10 | 表ドラ：ドラ表示牌の次の牌。カンのたびに新ドラをめくる |
| R-11 | 裏ドラ：リーチ和了時のみ。翻に算入。さらに的中した裏ドラの枚数分チップ（§2.5） |
| R-12 | 全赤：筒子の5・索子の5はすべてドラ。各色4枚の5を「赤3枚・金1枚」にする（R-13）。赤5・金5はドラ1として翻に算入 |
| R-13 | 金5：各色の5のうち1枚を金色にする（筒5・索5で計2枚）。点数は赤5と同じくドラ1。加えて和了手（手牌＋副露）にある金5の枚数分チップ（§2.5） |

### 2.3 花（4種）

花牌は配牌・ツモで手に入ったら即「抜いて」公開し、王牌から1枚補充する。抜いた花は和了時に効果を出す。

| ID | 花 | 効果 |
|---|---|---|
| R-20 | 春 | 抜いた春の枚数分チップ（ドラではない） |
| R-21 | 夏 | 和了の点数ランクを1つ上げる（満貫以下→満貫、満貫→跳満、跳満→倍満、倍満→三倍満、三倍満→役満扱い）。既存の役満には適用しない |
| R-22 | 秋 | 5の牌のドラが1つ増える（赤5・金5がさらに高くなる。翻に算入） |
| R-23 | 冬 | ドラ表示牌の隣から山の上の牌を順にめくる。自分の和了手と被ったら終了（被った牌は数えない）。めくれた枚数分チップ（ドラではない） |

確定：花は春夏秋冬の各1枚・計4枚。花は和了時のみ効果（流局では無効）。

### 2.4 白ポッチ（特別牌）

白ポッチは標準ルールの牌ではなく、麻雀牌セットに予備で入る「中央に点のある白」をローカルで特別牌として使うもの。ユーザー指定をそのまま仕様にする。

| ID | 内容 |
|---|---|
| R-30 | 白4枚のうち1枚を白ポッチに置き換える（白ポッチ＝1枚、通常の白は3枚）。山に混ぜる。総枚数は増えない |
| R-31 | リーチ宣言後、自分のツモ番で新しく白ポッチを引いたら、その局の自分の待ち牌のどれかとして扱い、ツモ和了できる（ツモ専用のオールマイティ） |
| R-32 | ロンには使えない。他家が白ポッチを捨てても和了にならない |
| R-33 | 白ポッチは普通の白としても使える。手に残して白の刻子・槓子・役牌・字一色・小三元などに使える（白として数える） |
| R-34 | 待ちが複数あるときは、最も高くなる待ち牌として解釈して計算する（本人有利） |
| R-35 | 白ポッチ自体は赤・ドラの対象にしない。白ポッチで和了したら1チップ（§2.5）。役は通常どおり（リーチ後ツモなのでリーチ＋門前ツモが付く） |
| R-36 | 白として手に組み込んでリーチした場合、その白ポッチは白として固定。万能牌になるのは「リーチ後に新しくツモった白ポッチ」だけ |
| R-37 | 白ポッチを白の4枚目として暗槓・加槓に使える。嶺上でさらに白ポッチを引いた場合はR-31にしたがう |

### 2.5 チップ（祝儀）

対局中に発生する祝儀をチップとして自動でやりとりし、終局後に対戦記録の精算へ合流する。

| ID | 内容 |
|---|---|
| C-01 | 1チップ＝100円。全員2,000円＝20チップのバイインで開始 |
| C-02 | チップが0になったら、再度2,000円（20チップ）バイインする |
| C-03 | チップは和了時の祝儀。支払いは、ツモ＝他家2人がそれぞれ枚数分、ロン＝放銃者が枚数分 |
| C-04 | もらえる枚数：裏ドラ的中＝的中枚数分／一発＝1枚／白ポッチで和了＝1枚／春＝抜いた枚数分／冬＝めくれた枚数分／金5＝和了手にある金5の枚数分 |
| C-05 | 赤5（金以外）・表ドラ・秋はチップ対象外（点数側だけに効く） |
| C-06 | チップは終局時に対戦記録のチップ精算（ゼロサム・バイイン制）へ合流する |

補足：裏ドラ・一発は従来どおり翻にも算入し、加えてチップも出る（＝ご祝儀）。春・冬はチップのみで翻には影響しない。

### 2.6 役

- 標準のリーチ麻雀の役＋役満（リーチ、一発、門前ツモ、平和、タンヤオ、北を含む役牌、一盃口、三色、一気通貫、チャンタ、七対子、対々和、三暗刻、三色同刻、混老頭、小三元、混一色、清一色、ジュンチャン、二盃口、海底・河底、嶺上開花、槍槓、ダブルリーチ、流し役満 など）
- 役満：国士無双、四暗刻、大三元、字一色、緑一色、清老頭、小四喜、大四喜、四槓子、九蓮宝燈、天和・地和
- ダブル役満：四暗刻単騎・国士無双十三面待ち・大四喜・純正九蓮宝燈
- ローカル追加：清一色の七対子は（単）役満として扱う
- 役満は複合すると加算（例：大三元＋字一色で2倍相当）。かぞえ役満は14翻以上（R-41）
- 包（パオ）・大明槓の責任払いは入れない

### 2.8 対局の進行・終局

| ID | 内容 |
|---|---|
| P-01 | 対戦記録のグループから卓に入室。3人そろったら自動開始。開始時に親（起家）をランダムで決める |
| P-02 | 待機中・空席を表示。全員接続で開始、1人でも抜けたら一時停止して再接続を待つ |
| P-03 | 東南戦。南3（オーラス）終了時に誰も40,000点を超えていなければ西場へ延長（場風＝西）。誰かが40,000点を超えた局の終了で終局 |
| P-04 | トビ（持ち点が0点未満）になったら即終局して精算へ |
| P-05 | 連荘はテンパイ連荘（親の和了、または親が聴牌で流局なら連荘、本場を加算）。親が子に放銃・ツモられたら親流れ |
| P-06 | 制限時間：1手ごとに持ち時間（基本10秒＋ストック20秒）。切れたら自動ツモ切り |
| P-07 | 同点時の順位は起家に近い席順を上位とする |
| P-08 | 途中流局はなし（九種九牌は入れない）。四風連打・四開槓も入れない |
| P-09 | 王牌（14枚：ドラ表示・裏ドラ・嶺上含む）を除いて山を引き切る。花・カンの補充は王牌から行い、生牌の末尾を王牌へ回して王牌を14枚に保つ |

## 3. 画面（最小・雀魂風）

- 卓：自分の手牌を下に大きく、他2人を上と左右に伏せ牌で。中央に捨て牌（3人分）、残りツモ数、ドラ表示牌、各自の点数・チップ・現在の親と場
- 自分の番：ツモ牌を手牌の右に少し離して表示。牌をタップで打牌。ツモ切りボタン
- 鳴ける・和了れるときだけ、ポン／カン／リーチ／ツモ／ロン／パスのボタンを出す
- 抜いた花・白ポッチは自分の席の脇に表示
- D-05 テンパイ表示：自分がテンパイしたら、待ち牌をどこか（手牌の近く）に表示する
- 和了時：手牌・役・翻・ドラ・花・チップの内訳・点数を出す。次局へ進むボタン
- スマホ縦画面を基本。キャラ・背景・音の演出は入れない（効果音はまず無音）

## 4. 技術・構成

| 層 | 採用 | 理由 |
|---|---|---|
| 卓のリアルタイム状態 | Cloudflare Workers ＋ Durable Objects（SQLite版）＋ WebSocket | 無料枠で使える。1卓＝1つのDurable Objectにして、全員の接続と本当のゲーム状態を集約。手牌を本人にだけ配れる |
| 画面 | React ＋ TypeScript（Vite）、PWA | 対戦記録アプリと同じ構成で統合・公開を使い回せる |
| ゲームのロジック | TypeScript の純粋関数（牌・和了判定・翻集計・固定点数表・チップ算出・1局の進行）。クライアントとサーバーで共用 | 画面や通信に依存させず、単体テストで正しさを固める |
| 公開 | Cloudflare（GitHub連携で自動デプロイ） | 対戦記録アプリと同じ |
| テスト | Vitest（ロジック）、手元スクリプト（進行・通信） | |

### 4.1 なぜサーバー集約（Durable Object）か
オンラインで手牌を隠すには、クライアントを信用できない。全員が同じ本当の状態をサーバーに1か所持ち、各プレイヤーには「見てよい情報」だけを送る。牌山のシャッフル・ツモ・和了判定もサーバーで行い、クライアントは表示と操作だけにする。画面を改造しても他人の手牌は見えず、点数もチップも偽れない。

### 4.2 通信の形（概略）
- 入室：グループから卓に接続。3人そろったら開始
- サーバー→各自：自分の手牌、全員の捨て牌・鳴き・点数・チップ・残り数など「公開情報＋自分の手牌」
- 各自→サーバー：打牌・ポン・カン・リーチ・ツモ・ロン・パスなどの操作
- サーバーが正当性を確認してから状態を進め、全員に差分を配る
- 切断時：席は残し、再接続で同じ卓に戻れる。全員が抜けてしばらくで卓を閉じる

## 7. 対戦記録アプリとの統合（合体）

| ID | 内容 |
|---|---|
| I-01 | 1つのリポジトリ・1つのデプロイにまとめる。既存のグループ／メンバー／セッション／精算／チップ／役満殿堂はそのまま使う |

## 8. 作る順番（段取りと理由）

正しさの要（和了判定・翻集計・点数表・チップ）を先に固め、通信と画面は後に回す。符がない分、点数側は固定表の対応だけなので、判定と翻の集計に集中できる。

- Phase 1 ルールのコア：牌の表現、和了判定（面子分解・七対子・国士）、待ち計算、役と翻の集計、固定点数表（R-42）、全赤・金5・花・白ポッチ・チップ算出。純粋関数＋Vitest。画面・通信なし
- Phase 2 1局の進行エンジン：配牌→ツモ→打牌→鳴き→リーチ→和了／流局を、サーバー側の状態機械として純粋に。DBG-01〜03で検証可能に
- Phase 3 Durable Object＋WebSocket：3人が接続して1局を回せる。手牌は本人にだけ送る
- Phase 4 画面（最小・雀魂風）：手牌・捨て牌・鳴き・各ボタン・待ち牌表示・和了表示
- Phase 5 半荘として通す：東南・西入・連荘・親移動・点数移動・チップ移動・ウマ・終局・対戦記録への自動登録
- Phase 6 仕上げ：切断と再接続、エラー表示、スマホ最適化、牌譜の再生

各Phaseの終わりに動かして確認し、報告してから次へ進む。

## 9. 確認したいこと（残り）

ほぼ確定。こちらで仮に決めた3点だけ、違えば直す。

| ID | 内容 | こちらの決め |

| Q-A | 金5の作り方（各色の5＝赤3・金1、計 赤6・金2）。金も赤と同じくドラ扱い＋金の枚数分チップ | この形で進める |
